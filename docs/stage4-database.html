4.7

Keputusan Database

KeputusanAlasan
JSON column untuk result_data 13 parameter menghasilkan struktur data berbeda (frequency array, mean scalar, competency matrix). JSON column lebih fleksibel daripada tabel terpisah per tipe. MySQL 8+ mendukung JSON natively dengan indexing.
Unique composite index (tracer_study_id + parameter_number) Menjamin tidak ada duplikasi parameter dalam satu tracer study. Sekaligus mempercepat query utama: "ambil semua parameter untuk tracer study X".
CASCADE on delete Ketika tracer study dihapus, seluruh analysis_results dan reports terkait otomatis terhapus. Menghindari orphaned records.
ENUM untuk status Hanya 4 kemungkinan status, jarang berubah. ENUM lebih efisien dan self-documenting daripada string bebas atau lookup table.
DECIMAL(5,2) untuk response rate Presisi 2 desimal cukup untuk persentase (0.00 – 100.00). DECIMAL menghindari floating-point rounding issues.
Tidak ada tabel users Sesuai keputusan: tidak ada autentikasi. Menghilangkan kebutuhan tabel users, password_resets, sessions, dan personal_access_tokens.
file_path relatif, bukan absolut Path disimpan relatif terhadap storage root ("reports/abc123.docx"), bukan absolut. Memungkinkan portabilitas antar environment.
