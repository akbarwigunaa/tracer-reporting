Use Case Diagram

7.3

Deskripsi Use Case

UC-01 Lihat Dashboard
AktorPengguna
DeskripsiPengguna melihat ringkasan seluruh tracer study yang telah diupload beserta statistik umum.
PreconditionAplikasi dapat diakses melalui browser.
TriggerPengguna membuka URL root (/) atau klik menu Dashboard.
Main Flow
  1. Sistem menampilkan 4 widget statistik: total tracer study, total responden, total laporan, upload terakhir.
  2. Sistem menampilkan tabel daftar tracer study (prodi, tahun, responden, status).
  3. Pengguna dapat klik "Lihat" untuk menuju halaman analisis detail.
  4. Pengguna dapat klik "Upload Baru" untuk menuju halaman upload.
PostconditionDashboard ditampilkan dengan data terbaru.
Alt: Jika belum ada data, sistem menampilkan empty state dengan tombol "Upload Data Pertama".
UC-02 Upload Data Tracer
AktorPengguna
DeskripsiPengguna mengupload file Excel (.xlsx) berisi data tracer study beserta informasi meta institusi.
PreconditionFile Excel tersedia dalam format template DIKTI (sheet "data tracer" dengan header di baris 3).
Includes«include» UC-03: Input Meta Institusi, «include» UC-04: Proses Analisis Otomatis
Main Flow
  1. Pengguna klik menu "Upload Data" atau tombol "Upload Baru" dari dashboard.
  2. Sistem menampilkan form upload dengan 2 bagian: informasi institusi dan file upload.
  3. Pengguna mengisi informasi institusi (→ UC-03).
  4. Pengguna memilih file Excel via drag-and-drop atau klik browse.
  5. Pengguna klik "Upload & Proses".
  6. Sistem memvalidasi input (format file, field wajib).
  7. Sistem menyimpan file sementara dan membuat record tracer_studies (status: processing).
  8. Sistem menjalankan analisis otomatis (→ UC-04).
  9. Sistem menghapus file Excel sementara.
  10. Sistem redirect ke halaman analisis dengan flash message sukses.
PostconditionRecord tracer_studies tersimpan (status: completed), 13 analysis_results tersimpan, file Excel dihapus.
Alt 6a: Validasi gagal → sistem menampilkan pesan error, form tetap terisi, pengguna memperbaiki input.
Alt 8a: Analisis gagal → status diubah ke "failed", pengguna diredirect ke dashboard dengan pesan error.
UC-03 Input Meta Institusi «include»
AktorPengguna (via UC-02)
DeskripsiSub-proses dari UC-02. Pengguna mengisi 5 field informasi institusi yang akan digunakan dalam laporan dan perhitungan response rate.
Main Flow
  1. Pengguna mengisi Nama Perguruan Tinggi (text).
  2. Pengguna mengisi Nama Program Studi (text).
  3. Pengguna mengisi Tahun Tracer (year, 4 digit).
  4. Pengguna mengisi Total Lulusan PT (angka positif).
  5. Pengguna mengisi Total Lulusan Prodi (angka positif).
PostconditionData meta tersimpan di kolom tracer_studies. Response rate dihitung otomatis: (total_responden / total_lulusan) × 100.
UC-04 Proses Analisis Otomatis «include»
AktorSistem (via UC-02)
DeskripsiSub-proses otomatis dari UC-02. Sistem membaca Excel, menghitung statistik 13 parameter, generate narasi dan konfigurasi chart.
Main Flow
  1. ExcelReaderService membaca sheet "data tracer" → array responden.
  2. Sistem menghitung total_responden dan response rate.
  3. Untuk setiap 13 parameter (loop):
  4.  a. StatisticsService menghitung statistik sesuai tipe (frequency/mean/sum/index).
  5.  b. ChartConfigService membangun konfigurasi Chart.js.
  6.  c. NarrativeService menghasilkan paragraf narasi.
  7.  d. Sistem menyimpan record analysis_results.
  8. Sistem mengubah status tracer_studies menjadi "completed".
Postcondition13 records analysis_results tersimpan dengan result_data (JSON), chart_config (JSON), dan narrative (text).
UC-05 Lihat Analisis Parameter
AktorPengguna
DeskripsiPengguna melihat hasil analisis lengkap: 13 parameter cards berisi tabel statistik, chart interaktif, dan narasi otomatis.
PreconditionTracer study berstatus "completed" (analisis berhasil).
Main Flow
  1. Pengguna klik "Lihat" pada tabel dashboard atau navigasi ke /analysis/{id}.
  2. Sistem menampilkan header: nama prodi, tahun, total responden, response rate.
  3. Sistem menampilkan 13 parameter cards secara berurutan (scrollable).
  4. Setiap card menampilkan: tabel data, chart (pie/bar/grouped bar), dan paragraf narasi.
  5. Pengguna dapat scroll untuk melihat seluruh parameter.
PostconditionHalaman analisis ditampilkan. Chart di-render oleh Chart.js di browser.
Alt 1a: Tracer study dengan id tidak ditemukan → sistem menampilkan halaman 404.
UC-06 Generate Laporan Word
AktorPengguna
DeskripsiPengguna men-trigger pembuatan dokumen laporan .docx dari hasil analisis tracer study.
PreconditionTracer study berstatus "completed" dengan 13 analysis_results lengkap.
Main Flow
  1. Pengguna klik "Generate Laporan Word" pada halaman analisis.
  2. ReportGeneratorService membuat dokumen .docx via PHPWord.
  3. Dokumen berisi: cover page, daftar isi, ringkasan, 13 bab parameter (tabel + narasi).
  4. File disimpan di storage/app/reports/.
  5. Record reports tersimpan di database.
  6. Sistem redirect ke halaman laporan dengan flash message sukses.
PostconditionFile .docx tersimpan di storage, record reports tersimpan di DB.
Alt 2a: Generate gagal → flash message error, tidak ada file/record yang tersimpan.
UC-07 Download Laporan
AktorPengguna
DeskripsiPengguna mendownload file .docx laporan yang sudah di-generate.
PreconditionLaporan sudah di-generate dan file ada di storage.
Main Flow
  1. Pengguna membuka halaman Laporan (/reports).
  2. Sistem menampilkan daftar laporan yang tersedia.
  3. Pengguna klik "Download" pada laporan yang diinginkan.
  4. Sistem mengirim file .docx sebagai download response.
PostconditionFile .docx terdownload ke komputer pengguna.
Alt 4a: File tidak ditemukan di storage → sistem menampilkan pesan error "File laporan tidak ditemukan".
UC-08 Hapus Data «extend»
AktorPengguna
DeskripsiPengguna menghapus tracer study (beserta semua analysis_results dan reports terkait) atau menghapus individual report.
PreconditionData yang akan dihapus ada di database.
Main Flow
  1. Pengguna klik tombol "Hapus" pada item yang ingin dihapus.
  2. Sistem menampilkan modal konfirmasi: "Yakin ingin menghapus?"
  3. Pengguna mengonfirmasi penghapusan.
  4. Sistem menghapus record dari database (CASCADE: analysis_results + reports ikut terhapus).
  5. Sistem menghapus file fisik .docx terkait dari storage (via model event).
  6. Sistem menampilkan flash message sukses.
PostconditionRecord dan file terkait dihapus permanen.
Alt 3a: Pengguna membatalkan → modal ditutup, tidak ada perubahan.
